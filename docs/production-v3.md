# V3 production and daily operation

Run `npm ci`, `npm run setup:v3`, then `npm run produce:daily` (or say PROCEED to the coding agent). Never upload automatically. The daily command performs new source retrieval, discovers GitHub Trending repositories, scores candidate records, excludes successful topic IDs, and renders only reviewed topics with real capture adapters. It returns a nonzero status for shortfalls. It is not a general AI script generator or universal browser agent: new discoveries require primary verification and a genuine capture/story adapter before eligibility. Never imply that unverified discoveries are ready to publish.

The current curated story file is `data/production-v3.json`. Reusable research is `TrendHunter.ts`; declarative timed scene production is `prepare-v3.ts`, real app adapters are `capture-v3.ts`, renderer is `FactoryShort.tsx`, caption grouping is `CaptionDirector.ts`, music/effects/mixing are `AudioDirector.ts`, encoded output verification is `verify-v3.py`. Legacy v1/v2 components and render commands remain intact. Schema accepts both creative versions.

Every selected story includes five honest hooks, selected-hook rationale, simple narration, actual acoustic timestamps, scene purposes, source-coordinate targets, evidence assertions, payoff, takeaway and concise subscription invitation. Contact sheets use actual encoded MP4 frames. Perceptual audio quality cannot be inferred from loudness measurements; listen before upload. No mandatory score of 10 is assigned.

Capture adapters run only local software: official CyberChef release, pinned Node-RED 5.0.9, pinned Playwright 1.58.2 Trace Viewer. The checkout fixture is explicitly fictional, not a third-party checkout or purchase. Node-RED's greeting flow is a trivial functional demonstration, not a production integration. Traces can contain sensitive data; public examples must contain only synthetic inputs.

Research freshness is tracked separately from product age. This run selected evergreen Node-RED and Playwright because cloud policy blocked new SaaS demos and macOS software was unavailable. They must not be described as recent launches. Product Hunt popularity is not evidence of YouTube performance. Unknown access, pricing and SaaS automation permissions remain unknown and block automated capture.

Reproduce this run from an available evidence directory: `npx tsx scripts/prepare-v3.ts OUTPUT_DIR`, `npx tsx scripts/render-v3.ts OUTPUT_DIR`, then `python scripts/verify-v3.py OUTPUT_DIR/TOOL` for each tool. Existing evidence can be reused only for rendering revisions, never presented as fresh daily product testing. Generate a unique output root for each new run. Preserve failed takes and nonzero outcomes in the report. Large footage, output and work directories are ignored by Git.
