# HumanVoiceDirector

The installed engine remains sherpa-onnx 1.12.26 with the Piper/VITS en_US-ljspeech-medium model, one speaker ID (0), 22,050 Hz output. Its installed API exposes speaker ID and speed; VITS configuration also exposes length/noise scales. It does **not** expose SSML, named emotions, expressive style prompts, native word timestamps, or a usable native fundamental-frequency contour API. A mode label is a direction for rate/pauses/emphasis, not evidence of learned emotion synthesis.

`src/directors/HumanVoiceDirector.ts` validates semantic phrases and supplies sentence-purpose defaults. `scripts/human_voice.py` implements the synthesis path. `scripts/tts.py` routes future calls through it unless `legacyFlatVoice: true` or config/voice.json has enabled=false. `src/services/narration.ts` validates cache identity against text, performance, voice-config hash and waveform hash; the daily v3 preparation path uses this helper. New versioned runs synthesize fresh audio; old MP4s remain untouched.

Five persisted presets: curious, excited, anticipation, explanatory, satisfied. Each uses conservative native rate changes, explicit 0–350ms phrase pauses and the same speaker/model. Strong emphasis is limited to two selected words per phrase and uses a smooth 0.9dB gain envelope located with acoustic word alignment. Excess edge silence is trimmed conservatively; 5ms fades apply at phrase boundaries, and spoken samples are never crossfaded over one another. Native question punctuation guides the engine's existing intonation; a question-contour guarantee is not claimed.

Optional Rubber Band processing uses pitch ratios of roughly 0.995–1.018 with formant=preserved and pitchq=quality, independently from speech speed. It was tested on a short sample. It is OFF by default and OFF in the final video because listening-based preference is unavailable. EQ is not used as a substitute for pitch, and playback-rate resampling is not used. No random pitch modulation or voice cloning is introduced.

Every phrase receives actual synthesis start/end metadata. After all rate, emphasis, pause, fade and optional pitch processing, the final waveform is acoustically forced-aligned again using PocketSphinx. Captions and scene boundaries consume the resulting words/phrases. `sourceNarration`, `sourcePerformance`, `voiceConfigSha256`, and waveform SHA-256 bind the timing sidecar to the delivered voice. Unknown pronunciations fail clearly rather than inventing timestamps; extend the explicit phoneme dictionary for additional product names.

`voice-quality.py` measures waveform integrity, timing, mode/rate variation, inserted pauses and autocorrelation-based F0 estimates. F0 statistics are descriptive and are not a naturalness score. A flat-versus-directed A/B pair is delivered for the experiment. Human listening must assess pronunciation, timbre continuity, naturalness, artifacts and emotional delivery before a human-level or perceptually approved claim. This environment's objective audio inspection does not provide that evidence.

Example: voicePerformance.version=1; phrases include text, emotion, optional rate, emphasis array, pauseBeforeMs, pauseAfterMs, and scene. Phrase texts must concatenate to the narration exactly. Script/video schema accepts the performance object. `npm run test:voice` rejects invalid rates/modes/pauses and checks the final acoustic timing evidence. A meaningful future improvement is a listener-reviewed expressive no-cost model with explicit native prosody controls; no paid-service migration was performed.
